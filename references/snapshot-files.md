# Files in a snapshot folder (kubegap reference)

Moved here from SKILL.md section 5. One snapshot (`<snapshot root>/<context>/<YYYY-MM-DDTHH-MM-SS>/`) holds the files below. The key shape of `summary.json` is in [summary-shape.md](summary-shape.md).

- `<context>/setup.json` (next to the snapshots, written by `kubegap setup`): the tool, context, store and AWS permission checks. `cluster.auth` records how the context authenticates: the exec command, its arguments and the names of its env variables; of the env values only `AWS_PROFILE` and `AWS_REGION` are kept (the profile value also appears as `cluster.eks.profile` here and in `inventory.json`), every other value is written as `<redacted>`.
- `inventory.json`: dict. `cluster{platform, platform_reasons, server_version, eks{version, control_plane_logging, control_plane_logging_off, endpoint_public, public_access_cidrs, secrets_encryption, support_type, addons{<name>: {version,status}}, nodegroups}}`, `profile{name, source, reasons}`, `node_access{method, ssm_registered[], ssm_unregistered[]}`, `nodes{count, ready, kubelet_versions[], os_images[], kernels[], runtimes[], architectures[], zones[], capacity_types[], nodes[{name, roles, instance_type, zone, capacity_type, nodepool, internal_ip, allocatable, capacity}]}`, `namespaces{count, names[], prod_like[], dev_like[]}`, `pods{count, by_phase}`, `storage_classes[]`, `crds{count, groups[]}`, `components{<name>: {present, family, evidence}}`, `components_present[]`, `families_present[]`, `missing_families[]`, `stores{prometheus|alertmanager|loki|grafana: {ok, version, retention, service}}`, `collectors_enabled[]`.
- `inventory.json` also carries `pod_metrics_targets{"<collector>.<step id>": {namespace, selector, port, workload, candidates[] (every workload the glob matched; the one in the step's default namespace is taken, else the first by kind, namespace, name), source{namespace, selector, port: discovered|config|default}, skip?}}`: where each `type: pod-metrics` step reads, decided at discovery from the fetched workloads, `components.<name>` in config.yaml and the step's defaults (lib/podmetrics.discover_targets, #136). `skip` names a metrics endpoint served over TLS with authentication, which the step does not read.
- `collect-result.json`: per collector `{collector, steps{<id>: {ok, error, skipped?, ...}}}` plus `_summary{mode, collectors[], steps, mode_skipped[], failed[], skipped[], seconds_total}`; a `type: pod-metrics` step's entry is `{ok, pods{<pod>: {ok, via (apiserver-proxy | node:<name>), node, out, error, skipped?}}, target (the inventory target it read), error, skipped?, note?}`; a `type: tool` kubent entry adds `api_read, lists_ok, lists_failed` (Lists answered and refused) and `manifests`, the objects with a last-applied annotation it logged; a pluto entry adds the same keys counted from `objects.dump-all` (kinds saved, kinds not permitted or failed, a failed API discovery counted as one) and `manifests`, the number of entries it was given. The `objects.dump-all` step also records `served` (every kind `kubectl api-resources --verbs=list` listed, as `name` for the core group and `name.group` otherwise), `written` (the file stems it wrote), `fetched_by_discovery` (the kinds lib/discover.py had saved, by full name; not `skipped`, which in a step record is the reason the step did not run), `excluded`, `not_permitted`, `failed{}` and `discovery_error`, the error of a `kubectl api-resources` that failed for at least one group, else null; `snapshot.object_file_status` judges a missing `objects/<stem>.json` against this record (#160). File names: the core group and the kinds `lib/discover.py` fetches carry the resource name (`pods.json`, `cronjobs.json`, also when the dump step fetched them because discovery failed), every other kind `name.group` (`jobs.batch.json`).
- `findings-draft.json`: dict. `findings` is a **list** (sorted by severity). Item: `id, check, name, area, type, status(fail|warn), severity_default, symptom_linked, target, evidence(string or list), instances, details(the material the rule judged, whole: a summary item's referenced keys, a metric's labels and value or values, an object's namespace/name/kind; a list when several instances merged into one target; when the evidence cuts a list, the full list is here), known_issues[{issue, note}](open defects of kubegap on this check, from rubric/known-issues.yaml; report-details.md writes `known issue #N` after the evidence), source, why, suggest, verify[], cases[], measured, notes, thresholds`. `check_results` is also a **list** (not a dict): `id, status(done|disabled|skip|error|tool-missing), counts{fail,warn,pass,excluded,gone_node}, reason, thresholds, rule_hash(12 hex characters over the verdict-deciding parts of the check, since rubric 0.1.66; diff compares it), gone_nodes[], known_issues[]`. Also `checks{total, by_status, load_errors}`, `findings_count`, `suppressed[]`, `expired_suppressions[]`, `llm_checks[]`, `severity_rules{levels, rules[]}`, `rubric_version`, `profile`.
- `findings-draft.json` `check_results[]` also carries, per check, `status` (`done`, `skip`, `not-collected`, `disabled`, `tool-missing`, `error`, `llm`), `reason` for anything but `done`, and for a `done` check whose rule has `needs`: `counts.skipped` and `skipped_reason` when some targets lacked the input (judged in part; section 7-5 lists them). A check whose targets all lacked it is `skip` with `nothing to judge: <reason>`, never a pass (#114).
- `diff.json`: dict. `inventory{...changes}`, `objects{kinds_compared, added[], removed[], changed[{kind,name,generation,changed_fields}], count_only{}, summary}`, `findings{counts_before, counts_after, new[], resolved[], changed[], rename_suspects[], criteria_changes{new_checks[], dropped_checks[], rule_changed[], thresholds_changed[], rule_unknown_checks[], note}(findings that appeared, disappeared or changed because the checks did and not the cluster: the check did not exist or was gated off by mode, profile, tool or error on one side, or its rule_hash differs, or the thresholds in force differ; each row: id, check, kind(new|resolved|changed), status, severity_default, check_status[a, b], check_reason[a, b], rule_hash[a, b]; these are kept out of new, resolved and changed. A check that was `skip` on one side, its inputs absent, is a cluster change and its new/resolved row carries check_status and check_reason. rule_unknown_checks are checks from before rule hashes while the rubric version differs; their findings stay in new, resolved and changed with `rule_known: false`), summary{new, resolved, changed, criteria_changes, rule_unknown_checks}, persisted{runs_checked, max_runs, persisted_3plus, persisted_all, toil_candidates_by_check{<check-id>: n}, rows[{id, runs, check, status, severity_default}], note}}` (`persisted` = walk back through up to 10 earlier snapshots of the same context and count how many consecutive times this finding appeared — material for the Toil candidates in the report), `events{changed[], warning_reasons_new[]}`, `metrics{<query-id>: {series, appeared, disappeared, top_deltas[]}}`.
- `objects/<kind>.json`: kubectl's `{"items": [...]}` with two exceptions (lib/scrub.py): Secrets have no `data`/`stringData`; ConfigMap `data` values are `{len, shape}` (and `binaryData` `{len}`), and so are the two annotations that copy the object, `kubectl.kubernetes.io/last-applied-configuration` and `objectset.rio.cattle.io/applied`; ConfigMaps keep `metadata.managedFields` (fetched with `--show-managed-fields`, key names and change times only) for hygiene.config_changes except the configuration keys kubegap parses, and each ConfigMap carries `kubegap_scrub{values_dropped, kept_keys[], data_chars, secret_like_keys[], annotations_dropped[]}`. `events.json` is kubectl's output as-is. `metrics/<id>.json`: `{id, query, why, ok, result[{metric{}, value[ts, "value"]}]}`. `metrics/series-present.json`: `{names{<metric name>: <series now>}}`, one entry per metric name the queries of every metrics.yaml cite in `source:` (lib/metricnames.py), written by lib/prom.record_series_present with one `count by (__name__)` query per file; 0 means Prometheus has no series of that name, which turns an empty query result into a skip naming it (#141). `logs/pods/`: in a full run the component pod logs are written here, read by summarize (`summary.logs`, Karpenter timings in `summary.scaling`) and then deleted; `logs/pods/REMOVED.txt` and `logs/pods/AGGREGATED.json` (`{removed_at, files_removed[], log_scan{…the scan keys of summary.logs…}, karpenter_logs{latency_24h, nodeclaims_launched_24h, disruptions_24h, disrupted_24h, launch_failures_24h}}`) remain unless `keep_component_logs: true` is set; a rerun of summarize reads the aggregate instead of the logs. `summary.logs.component_logs_removed` records which.
- `tools/helm-list.json`: `helm list -A -o json`, release metadata only; release values are never collected. `grafana/dashboards/<uid>.json`: Grafana `/api/dashboards/uid/<uid>` (only with a token). Every HTTP reply from a store (Prometheus, Alertmanager, Loki, Grafana) is read up to 64 MiB (`HTTP_MAX_BYTES` in `lib/http.py`); a larger reply fails the step with "response larger than 64 MiB" and nothing of it is written. `aws/acm-certificates.json`, `aws/service-quotas-<service>.json`, `aws/cw-quota-usage.json`, `aws/ec2-root-volumes.json`, `aws/cw-ebs-volumes.json`: results of the EKS platform collector's ACM, Service Quotas and generic CloudWatch step (`cw-metrics`, `lib/cwmetrics.py`). Summarized in `summary.eksplatform`.

## Where snapshots live

Moved here from SKILL.md section 0.

- **Root.** `~/.kubegap/snapshots/<context>/<YYYY-MM-DDTHH-MM-SS>/`, outside the skill folder, so cluster data never accumulates in the skill repository. Override with the `$KUBEGAP_SNAPSHOTS` environment variable, `snapshots_root` in config, or `--snapshots-root`.
- **The context folder** (`<root>/<context>/`) holds, next to the snapshot folders: `setup.json` (the last `setup` result), `answers.json` (the first-run questions the user answered or skipped, `lib/firstrun.py`), `node-access.json` (the last `kubegap nodes` probe: which nodes answered, and why the others did not) and `history.csv`.
- **`INCOMPLETE`** in a snapshot folder means collect did not finish: the snapshot is excluded from `latest` and from comparison baselines. If you analyze it anyway, write "collection incomplete" in report section 7-1.
- **Collection summary.** `_summary{collectors[], steps, failed[], skipped[], seconds_total}` in `collect-result.json` is the top-level summary of collection success; per-collector detail is under the keys below it.
- **Pruning.** `$KUBEGAP/scripts/kubegap prune --keep-daily N --keep-full M` removes old snapshots; the latest complete daily and the latest complete full always stay.
